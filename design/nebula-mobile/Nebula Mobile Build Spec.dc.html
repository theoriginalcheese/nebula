Nebula Mobile — build specification

iOS companion app for the Nebula desktop recorder · v1.0 spec · 18 Nov 2026

Visual source of truth: Nebula Mobile App Pages (3a–3h), Prefs Mobile Aesthetic R2 (backgrounds 2a–2l, Now layouts 2f–2h), and nm-space.js (background renderers). Where this document and a mockup disagree, this document wins on behaviour and the mockup wins on pixels.

How to use this document

  • Build in the order of §15 (Build order). Each phase has acceptance checks; do not start the next phase until they pass.
  • Every number in this document (sizes, colours, durations) is normative. If you need a value that is not here, take it from the mockup file named in the section, never invent it.
  • Text in mono is an identifier, file, or literal UI string. Quoted UI copy must be used verbatim.
  • “MUST” is a requirement, “SHOULD” a strong default, “MAY” optional. Anything marked Open question (§16) needs a decision from the owner before it is built — stub it, don’t guess.

1. What the product is

Nebula is a Windows desktop app that watches for games, drives OBS over its WebSocket API, and files every recording into a per-game folder (Videos\Nebula\<Game>). It classifies apps as games (Steam library auto-classifies; anything else triggers a one-time “Is this a game?” prompt, remembered forever), pauses on idle, discards tiny accidental clips, offloads to a NAS, and launches Moonlight for remote play over Tailscale.

Nebula Mobile is a companion that lets the user, away from the desk: see and control the current recording; answer “Is this a game?” prompts; browse, play and share clips; set per-game capture behaviour; start a Moonlight stream; and change the subset of settings that make sense from a phone.

The phone never talks to OBS directly. It talks only to the Nebula desktop app (“the PC agent”), which remains the single source of truth for state, settings and files.

Out of scope for v1: recording on the phone itself; editing clips beyond trim; multiple paired PCs at once (one active PC; switching is allowed); Android; iPad-specific layouts (iPad runs the iPhone layout scaled); macropad configuration.

2. Architecture

2.1 Components

  • PC agent (inside the existing desktop app): exposes a local API on ws://<host>:47990/nebula (WebSocket, JSON) and http://<host>:47990/files/… (HTTP range requests for clip streaming, thumbnails). Reachable on LAN and over the Tailscale interface. Port is configurable on the PC.
  • iOS app: SwiftUI, iOS 17+, iPhone only. A single AgentClient owns the socket; all screens observe one AppStore (observable state). No screen opens its own connection.
  • Live Activity + widget extension: shows the recording clock on the Lock Screen / Dynamic Island while recording.
  • Push relay (small hosted service): forwards PC-originated events (unknown app, recording started/stopped, offload finished) to APNs when the app is not foregrounded. The PC agent posts to the relay with the device token received at pairing.

2.2 Pairing

  1. On the PC: Settings → Remote → “Pair a phone” shows a QR code encoding {host candidates[], port, pcName, pairingToken (single use, 5 min TTL), pcPublicKey}.
  2. The phone scans it (first-run screen, or Settings → Studio PC → “Pair another PC”), connects to the first reachable host candidate (Tailscale IP first, then LAN IPs), and sends pair.request {pairingToken, deviceName, devicePublicKey, apnsToken}.
  3. The PC shows a toast “Allow <deviceName>?”; on accept it returns a long-lived deviceToken. The phone stores it in the Keychain. All later connections send it in hello.
  4. Unpairing on either side revokes the token; the phone returns to the first-run screen.

2.3 Sync model

  • On connect, the phone sends hello; the PC replies with a full snapshot (session, games, settings, pending apps, last 50 clips, peers). After that the PC pushes event messages; the phone never polls.
  • The recording clock is computed on the phone from session.startedAt and session.pausedTotal, so it ticks smoothly without a message per second. Live stats (bitrate, fps, GPU temp, audio levels) arrive as stats events at 1 Hz (audio levels 4 Hz) only while a Now screen is visible; the phone sends stats.subscribe / stats.unsubscribe.
  • Commands are optimistic: update local state immediately, send the command, and revert with a toast if the PC answers error or no ack arrives within 4 s.
  • Reconnect with exponential backoff (0.5 s, 1, 2, 4, 8, max 15 s). On reconnect, request a fresh snapshot and replace state wholesale.

5. App structure and navigation

  • Root: a floating glass tab bar with four tabs, in this order: Now, Clips, Remote, Games. Each tab has its own NavigationStack and keeps its scroll position and stack when you switch away.
  • Settings is not a tab. It opens as a full-height sheet from the sliders button (42 pt glass circle, top right of the large-title row) on Now, Clips and Remote. Games uses that slot for “+” (add a game by exe name). Settings has a “Done” button top right; sub-pages push inside the sheet with a standard back chevron labelled “Settings”.
  • Clip detail pushes on the Clips stack (and on the Now stack when a clip is tapped from Now). The tab bar stays visible.
  • “Is this a game?” sheet is a modal sheet presented over whatever is on screen (detents: medium on SE-size screens, large otherwise). It covers the tab bar.
  • Deep links: nebula://now, nebula://clip/<id>, nebula://pending/<id>, nebula://settings/<page>. Notifications and the Live Activity use these.

7. Motion

7.1 Curves

All UI transitions use a spring equivalent to cubic-bezier(.32,.72,0,1): SwiftUI .spring(response: 0.45, dampingFraction: 0.86). Durations: segment/selection 0.35 s, chips 0.4 s, card insert/remove 0.5 s. Press state: scale 0.98 over 0.15 s. No linear or ease-in-out curves in UI.

7.2 Rolling clock

Each digit is a vertical strip 0–9 clipped to one line; on change, the strip translates to the new digit over 0.6 s with the spring above. Colons don’t move. Format HH:MM:SS with leading zero hours in the hero (e.g. 01:12:04). The clock freezes while paused and is ink-2 (not gold) while paused.

7.3 Reduce Motion and Still

If iOS Reduce Motion is on or PhonePrefs.motion == "still": backgrounds render one frame (t = 20 s) and stop; the clock updates without rolling (cross-fade 0.15 s); springs become 0.2 s fades; live meters update without width animation. The background still re-renders when the user changes it.

Recording state machine (driven only by session.state from the PC; the phone never infers it):

idle ──game launches (capture=record|both) or session.start──▶ recording
idle ──game launches (capture=buffer)────────────────────────▶ bufferOnly
recording ──session.pause or idle timeout──▶ paused ──session.resume or input──▶ recording
recording | paused ──session.stop or game exits──▶ idle   (clip finalised; if duration < discardUnder it is deleted and no clip.added is sent)
bufferOnly ──replay.save──▶ bufferOnly (clip.added kind=replay)
bufferOnly ──game exits──▶ idle

  • Auto-pause & cleanup: “Pause when idle” stepper 1–60 s (step 1); “Discard clips under” stepper 0–120 s (step 5; 0 shows “Off”); “Keep recording while these play audio” chips (teal, mono) + “+ Add app” (picks from the PC’s running audio sessions). Steppers write on release with a 600 ms debounce.
  • Recording folder: read-only mono path + “set on PC”.
  • Phone-writable keys are exactly: launchCapture, replaySeconds, idleTimeout, discardUnder, keepAliveApps, offload.auto, gameListSync.provider. Everything else is read-only on the phone.

10. Backgrounds engine

Reference implementation: nm-space.js (Canvas 2D). Port to Metal (MTKView) or SpriteKit; the algorithms and constants are the spec. One renderer instance draws one background into one shared texture per frame; every visible screen composites that same texture full-screen behind its content (never one renderer per screen).

  • Coordinate space: all constants assume a 402×874 logical canvas. Scale uniformly by screen width; anchor bottom-aligned art (planets, galaxy, ringed) to the bottom edge.
  • Frame budget: target 20 fps for backgrounds (UI stays 120 Hz), ≤ 4 ms GPU per frame on A17. Pause rendering when the app is backgrounded, when a full-screen video plays, in Low Power Mode (render one still frame), and above 40 °C thermal state serious.
  • Space backdrop (shared by planet, solar, ring, galaxy, saturn): fill #06050C; diagonal galactic band — a radial gradient rotated −0.9 rad, squashed to 0.2, violet .34 → magenta .05 → 0, with a faint warm core; 190 seeded stars (seed 11) drifting horizontally at 0.3–1.3 pt/s, twinkling, the brightest few with a 4-point glint.
  • Earth: per-pixel lit sphere, radius 560, cap 236 pt visible, axial tilt 1.15 rad, light vector normalised (0.62, 0.5, −0.18) — sun behind the upper right, so most of the disc is night. Day texture × diffuse; city-lights texture on the night side tinted (255,205,140) × (1 − day)²; clouds rotate 1.25× surface speed; atmosphere fresnel (1 − n·z)^2.6 tinted (110,140,255); ocean specular. One rotation per 240 s. Textures: NASA Blue Marble / Black Marble equirectangular, 2048×1024, bundled in the app.
  • Random planet: equirectangular texture generated once per seed from 3D fBm on the sphere (no seam). 60% gas giant (latitude bands warped by noise, 1–3 storms) / 40% rocky (6-octave height ramp + polar ice). Palettes are the five gas and four rock palettes in PAL_GAS / PAL_ROCK. Name = two syllables + suffix from the seeded RNG. Cache generated textures by seed.
  • Moonrise: radius 420, cap 250, light (0.78, 0.5, 0.05) — side-lit, no clouds, faint atmosphere. Lunar albedo texture.
  • Solar live: real heliocentric longitudes for now from mean orbital elements (J2000 mean longitude + daily rate, table in PL); circular orbits; display radius 26 + 58·√a; ellipses squashed 0.34; camera yaw drifts 0.012 rad/s. Depth-sort planets around the Sun. Earth ringed in pulsing gold and labelled “EARTH · YOU”. Date stamp “LIVE · 18 NOV 2026” bottom left. Recompute longitudes once a minute.
  • Dot bloom: 8 pt dot grid on #100D1C; four superellipse (p = 3) metaball cores wandering on sinusoidal paths (periods 17–29 s); dot radius 0.75 + 2.75·e, colour violet → magenta → ink with amber where field > 1.1; a ring pulse radiates from (201, 300) every 7 s.
  • Pixel orbit: 4 pt cells; two tilted rings (axis −20°, squash 0.36) centred (250, 330): outer R 236 × 9 rows “trail” pattern at 14°/s; inner R 170 × 6 rows “blocks” at −7°/s, 80% intensity. Depth shading by angle.
  • Galaxy: 4 pt cells, centre (210, 700), tilt −24°, squash 0.42; two log-spiral arms rotating 0.05 rad/s; core gold-white; alpha = smoothstep(0.06, 0.7, density). Cell dropout uses a static per-cell hash (time-varying hashes cause visible jitter — do not).
  • Ringed: 4 pt cells; planet R 92 at (250, 712) with eight Nebula-palette bands drifting; ring 124–214 with a gap at 168–177, rotating 9°/s; drawn back-half ring → planet → front-half ring.
  • Dither: 4 pt cells on #0B0916; domain-warped fBm clouds quantised to six palette steps with a 4×4 Bayer matrix; drift 0.05 units/s.
  • The hero card and the top 450 pt of every screen must stay readable on all nine — art that matters lives in the lower third or behind glass. Verify each background with every screen (§14).

11. Copy rules

  • Sentence case everywhere except eyebrows (uppercase via styling, not in the string).
  • The PC is always called by its name (“Studio PC”), never “your computer” or “the host”.
  • Never show a value the PC hasn’t sent: unknown durations/sizes are “—”. Never show IPs or ping.
  • Times: “8:12 pm” (locale short), relative under an hour (“12 s ago”, “2 h ago”). Sizes: one decimal under 10 GB (“8.4 GB”), none above (“212 GB”).
  • Use the curly apostrophe (’) in all strings.

12. Accessibility

  • VoiceOver labels: the clock reads “Recording, 1 hour 12 minutes 4 seconds” and updates at most every 10 s; Stop is “Stop recording”; tiles read as one element (“Storage, 62 percent used, 212 gigabytes free, about 4 days left”).
  • Backgrounds are decorative: accessibilityHidden(true).
  • Reduce Transparency: all glass and glass reading surfaces become opaque #1C1730 / #100D1C.
  • Increase Contrast: hairlines go to .2 alpha; ink-3 becomes ink-2.
  • Colour is never the only signal: offload state, online state and drops also carry text.

13. Edge cases

  • Recording started on the PC while the phone is closed: on open, Now shows playing with the clock already correct (derived from startedAt).
  • Clock skew: compute elapsed as serverNow − startedAt − pausedTotal using the server time offset measured at hello.
  • Clip discarded for being short: it never appears; if the phone had optimistically shown it, remove it silently.
  • Two phones paired: both get pending prompts; the first answer wins, the other receives app.resolved.
  • Game renamed on PC: match by game id, not name.
  • Deleting a clip that is currently offloading: PC cancels offload first; phone shows the confirmation copy with “It’s still being copied to nas-vault.” appended.
  • Trim while offloading or writing: disabled with reason in a footnote.
  • Storage below 5%: Storage tile ring and label turn coral; push “Studio PC is almost out of space”.
  • Textures fail to load (corrupt bundle): Earth falls back to Random planet seed 3; Moonrise falls back to the space backdrop only.

14. Acceptance checklist

  1. All screens match mockups 2f/2g/2h and 3a–3h within 2 pt on a 402×874 simulator, in both Playing and Not-playing states, on all nine backgrounds and all three surface modes.
  2. The clock never jumps or stutters across pause/resume, reconnect, or app relaunch.
  3. Every command reverts with a toast when the PC is offline or errors.
  4. Answering “Is this a game?” from the sheet, the Games card, and the push notification all produce the same PC state, and the other surfaces update within 1 s.
  5. No text over glass falls below 4.5:1 contrast on any background (screenshot audit).
  6. Background rendering stays within budget for 10 minutes on device with no thermal warning; it pauses when backgrounded.
  7. Reduce Motion, Reduce Transparency, Increase Contrast and Dynamic Type AX1 all behave as §12 describes.
  8. Nothing scrolls under the tab bar without the 110 pt inset; nothing overlaps at any Dynamic Type size.

  1. PC agent API with a mock mode that replays a scripted session (idle → recording → pause → resume → stop, one pending app, 20 clips). The phone is developed against the mock. — Done when: a test client can run the full scripted session and every command in §4 acks or errors as specified.
  2. Phone shell: AppStore, AgentClient, pairing, global states (§8), tab bar, Settings sheet, empty screens. — Done when: pair/unpair works against the mock, and killing the mock shows PC offline after 3 s and recovers on restart.

  4. Backgrounds: space backdrop + Earth first, then the rest; Appearance screen. — Done when: all nine render within the §10 budget, pause when backgrounded, and switching from Appearance updates every tab.
  5. Now (2f playing + idle), then 2g, 2h. — Done when: every session state in Figure 2 renders correctly in all three layouts, and the clock survives pause, reconnect and relaunch.
