Reduced motion keeps the colour. Under prefers-reduced-motion — or the Settings toggle — every layer stays exactly where it is via animation-play-state:paused. Nothing is removed, nothing goes flat.
In-window panels sit on rgba(16,13,28,0.72–0.92) so the aurora reads through them while text keeps its contrast. A fully opaque panel over the aurora is a bug.
Build order & don't-forget
1Chassis first. Tray, core, titlebar, rail, empty pane. Nothing else until this matches 2a exactly.
2Hero card + its 3 states (2f–2h) driven by one state enum. Stat tiles and activity log next.
3Tray + window chrome. − and × both hide; Quit only in the tray menu; tray icon reflects state.
4Single-slot toast. Replace-in-place, 4s drain, hover freeze. Build the replace path before the visuals.
5Clips pane with real thumbnails, length, size, and the three row actions. Empty state = the min-clip note only.
6Settings with the key labels visible in mono under each field — they are part of the design, not a debug aid.
7Games, Macropad, mini overlay last. Mini overlay never shows while idle.
No emoji, no gradient floods, no second accent hue. Ember is live-and-errors only.
Every card is two layers: tinted outer shell, darker inner core. A flat card is a bug.

Trailing icons on primary pills live in their own 26–28px circle, flush to the right padding.
The background is randomised per launch — never hard-code blob positions or star coordinates.

06 · Feature deep-dives

Section 05 gives the numbers. This section gives the construction — layer order, literal declarations, and a side-by-side of the wrong build against the right one for each thing the last pass missed. Where a panel says Wrong, that is a real defect from the current implementation, not a hypothetical.

6a
6.1 — The living background

This is the feature the build missed hardest. It is two moving layers, not one: a slow aurora and a slower star drift. The current build has stars only, at uniform size and alpha, sitting on top of the interface. All five numbered layers below are mandatory and they stack in exactly this order.

Single biggest defect

Star dots are currently painted above the rail and the cards. The whole background stack lives at z-index:0 behind the chrome — never inside it, never over it.

Layer stack, back to front
0Ground gradientradial-gradient(150% 110% at 50% -10%, #12101F 0%, #0A0812 58%)
1Aurora blobs ×3blur 54–110px · alpha .22 / .22 / .07 · 46–92s
2Star dust — near1–1.9px · alpha .24–.85 · 120–170s
3Star dust — far1–1.3px · alpha .14–.5 · 190–260s · opacity .7
4Vignetteradial-gradient(140% 120% at 50% 34%, transparent 46%, rgba(0,0,0,.55))
5+All interface chromez-index:1 · translucent · NOTHING above it from layers 0–4
Wrong — current build

Uniform grid of identical pure-white dots, static, drawn over the chrome. No aurora, no vignette, no size or alpha variation, no drift. Reads as noise, not depth.

Right — live, this frame

Aurora drifting underneath, two dust layers at different speeds and randomised sizes, vignette pulling the corners down, chrome translucent on top so the colour reads through it.

Aurora blob — per element
position:absolute; border-radius:50%;
width:42–58%; height:56–88%;
background:radial-gradient(circle,
  rgba(139,124,246,.22), transparent 68%);
filter:blur(54px); /* 90–110px page-level */
animation:nbBlob rnd(46,92)s ease-in-out infinite;
animation-delay:-rnd(0,60)s;
animation-direction:rnd(normal|alternate);

Three per surface: accent .22, deep indigo .22, ember .07. The ember one is what keeps the ground from going cold — do not drop it.

Star dust — per layer
height:200%; /* so -50% loops seamlessly */
background-image: N × radial-gradient(
  rnd(.65,1)×1.9px at rnd()% rnd()%,
  rgba(217,212,255,rnd(.28,1)×.85), transparent 60%);
animation:nbDust rnd(120,170)s linear infinite,
  nbTwinkle rnd(7,13)s ease-in-out infinite;
animation-delay:-rnd(0,90)s, -rnd(0,8)s;

Near layer N = star density (default 34). Far layer = 0.75×N, max size 1.3px, max alpha .5, wrapper opacity .7, 190–260s. Colour is always rgba(217,212,255,α) — never #fff.

Randomise at launch

Every rnd() above is evaluated once on start-up, not baked into a stylesheet. Two sessions must never look identical. Seed nothing.

Freeze, keep colour

animation-play-state:paused on every layer under prefers-reduced-motion or the Settings toggle. Never remove a layer, never flatten to a solid.

Cost ceiling

Only transform and opacity animate. Set will-change on the moving spans only. No JS per frame except the pointer handler.

07 · New features — full spec

Deletion safety

Cull moves to the Recycle Bin, never unlinks. Always show the file count and total before acting, always exclude marked clips and replays, and never cull while recording.

When it speaks

One toast at disk_warn_days, once per day maximum. Below disk_block_below_gb the hero card refuses to start and offers the cull — better than a failed recording.

Don't

Don't show a pie chart, don't colour the bar by percentage thresholds, don't animate the fill on every refresh. The number is the message.

Apply sequence — order matters
1Game detected → look up profile, fall back to default
2SetVideoSettings — res + fps, only if changed
3SetProfileParameter — encoder + bitrate
4SetCurrentProgramScene — if scene set
5Wait for confirmation, then StartRecord
!Never apply mid-recording. Queue it for the next start.
!Log every applied change to the activity feed as [Profile].
Scope guard: resolution, fps, encoder, bitrate, scene. That is the whole feature. No audio tracks, no filters, no output paths, no encoder presets — those stay in OBS, and Nebula must never silently overwrite settings the user changed there.
