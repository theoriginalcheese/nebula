# t005
status: done

## Root cause

Two independent bugs, both silent:

1. **Wrong thread.** `toast_replace()` called `webview.create_window()` from
   Monitor / `call_soon` worker threads. pywebview only registers a native HWND
   when creation runs on its WinForms thread. v3 avoided this with
   `self._ui(lambda: self._toast_replace(...))`; v4 had no equivalent.

2. **Wrong coordinates.** `_toast_workarea()` returns physical pixels (DPI-aware
   `GetMonitorInfo`), but pywebview multiplies `x`/`y` by monitor scale again.
   The toast was created ~540px below the work area on 150% panels — a HWND
   titled "Nebula Toast" existed but sat off every visible monitor.

## Changed

- `spike/windows.py`
  - `_run_on_gui()` — marshal toast/overlay ops through `host.window.native.Invoke`
  - `_monitor_scale()` / `_toast_place()` — logical placement for pywebview
  - `ToastController.replace()` → `_replace_gui()` on GUI thread
  - `_create` uses rest position (rise is CSS-only); checks `create_window` return
  - `_toast_content` accepts string `details` (probe in the brief)
  - Overlay show/hide/sync/destroy use the same GUI dispatch
- `tests/test_v4_windows.py` — headless replace-in-place + GUI dispatch checks
- `shots/t005-toast.png` — live capture after fix
